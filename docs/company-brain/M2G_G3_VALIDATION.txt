== FINAL SEMANTIC CLOSURE — Issues 1–5 (M2G-G3 FINAL SEMANTIC CLOSURE) ==

  Issue 1 — Strict winner validation (evaluateFounderDecision Phase 3):
    When candidates !== null, Phase 3 now requires:
      (a) governingClaimId exists and is non-null/non-empty — returns {valid:false, reason:'missing governingClaimId'} if absent
      (b) governingClaimId maps to an ACTIVE candidate in the provided list
      (c) candidate.topic === decision.target — cross-topic winner rejected even when candidate is ACTIVE

    Null-governingClaimId decision (decision-219-oos) fails Phase 2 before reaching Phase 3 → unaffected.

  Issue 2 — doesDecisionCoverConflict binds winner to conflict candidateKeys:
    (a) Returns false immediately when governingClaimId is null (no winner → cannot cover any conflict)
    (b) Added: winner.graphNodeKey must appear in pc.candidateKeys for the conflict to be covered
    Topic+scope alone are insufficient — the winner must participate in the specific conflict's candidate set.
    G3-consistency-3: still passes because pairwise conflicts between atlas-exception and COMPANY candidates
    include atlas-exception's graphNodeKey in their candidateKeys; the atlas decision covers those.

  Issue 3 — buildG3DwIntelligenceContext per-topic conflict resolution:
    Replaced single resolvePolicy(topic:null) for policyConflicts with a per-topic resolution loop:
      - Enumerate distinct topics from all candidates
      - Call resolvePolicy(scope, topic) for each topic
      - Merge/deduplicate conflicts by (conflictClass, sorted candidateKeys)
    Invariant enforced: for every scope+topic, DW Intelligence conflict state ===
      resolvePolicy(scope, topic).detectedConflicts. Cross-topic CONTRACT pairings eliminated.

  Issue 4 — applyFounderDecisions picks newest fully valid decision:
    Previously: filtered by Phase 1+2, sorted, picked newest, ran Phase 3 on that one.
    A newer malformed decision (null/wrong-topic governingClaimId) masked a valid older one.
    Fix: evaluate Phase 3 on ALL Phase-1+2-valid decisions; keep only fully valid; sort; pick newest.
    Older-but-valid decisions are no longer masked by newer-but-malformed ones.
    Malformed decisions remain auditable in result.invalidatedDecisions but are excluded from
    result.decisions, which contains only fully valid current decisions.

  Issue 5 — CONTRACT provenance fix not regressed:
    rootSourceVersionIds overlap check, DERIVED_FROM edge scan, topic-specific behavior, and
    non-contract CSV negative case (test-217) all verified unchanged via full test suite.
