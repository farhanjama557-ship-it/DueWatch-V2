== TRUE FINAL EXIT PATCH — Issues 1–5 (M2G-G3 TRUE FINAL EXIT PATCH) ==

  Issue 1 — Shared evaluateFounderDecision (3-phase):
    New function evaluateFounderDecision(d, {brain, tenantId, topic, scope, candidates})
    returning {valid, winner, reason}. Three phases:
      Phase 1: structural validity (tenantId, status=RECORDED, evidenceClaimIds active)
      Phase 2: scope validation (CLIENT vs COMPANY, exact clientId match)
      Phase 3: winner-candidate validation (governingClaimId → ACTIVE candidate in candidates list)
    isFounderDecisionValid becomes thin wrapper (candidates: null, skips Phase 3).
    doesDecisionCoverConflict checks winner-candidate existence before topic/scope.
    applyFounderDecisions uses evaluateFounderDecision with Phase 3 (candidates list provided).
    askDwPolicy uses evaluateFounderDecision with scope-appropriate candidates for Phase 3
      (founderDecisionCandidates from scopeResolution, not questionType-based primaryResolution).
    buildG3DwIntelligenceContext uses evaluateFounderDecision for founderDecisions and
      produces invalidatedFounderDecisions for decisions that fail any phase.

  Issue 2 — CONTRACT provenance structural fix:
    CONTRACT_VS_COMPANY_POLICY fires only when a CLIENT policy candidate's
    provenance.rootSourceVersionIds overlaps with contract-derived CLIENT_EXCEPTION nodes'
    rootSourceVersionIds (found via DERIVED_FROM edge scan in graph snapshot).
    CSV-based CLIENT_EXCEPTION POLICY_CANDIDATEs have no DERIVED_FROM edge → no overlap → no fire.
    buildPolicyCandidates topic fix: topic now uses node.data?.policy_topic for CLIENT_EXCEPTION
    nodes (so atlas-exception.md appears in clientActiveForTopic with topic='late_fee_policy').

  Issue 3 — Replace G3-consistency-4 with true adversarial regression (test 217):
    Old test 215 (G3-consistency-4) removed.
    New test 217 verifies 4 explicit preconditions before asserting CONTRACT does NOT fire:
      Pre-1: active contract exists for testco
      Pre-2: active COMPANY late_fee_policy candidate exists
      Pre-3: active CLIENT late_fee_policy candidate exists for testco
      Pre-4: CLIENT candidate is NOT contract-derived (no DERIVED_FROM edge to contract node)
    Then asserts CONTRACT_VS_COMPANY_POLICY absent from resolvePolicy.conflicts.

  Issue 4 — DW Intelligence uses same G3 conflict computation as resolvePolicy:
    buildG3DwIntelligenceContext now calls resolvePolicy(topic=null) for the context scope.
    policyConflicts = policyResolution.detectedConflicts (same computation path as resolvePolicy).
    Test 218 proves resolvePolicy and buildG3DwIntelligenceContext agree on CONTRACT presence
    for atlas scope.

  Issue 5 — Return only currently valid founder decisions in DW Intelligence:
    buildG3DwIntelligenceContext.founderDecisions filtered via evaluateFounderDecision with
    contextScope (CLIENT:clientId when clientId provided, COMPANY otherwise) + Phase 3 candidates.
    invalidatedFounderDecisions: all tenantId-matching decisions that fail any phase, annotated
    with invalidReason explaining which phase/check failed.
    Test 219 proves: CLIENT-scoped decision absent from COMPANY context founderDecisions;
    decision with revoked evidence claim absent after revocation; both appear in invalidatedFounderDecisions.
