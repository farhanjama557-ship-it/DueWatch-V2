== Architecture ==

G4 consumes CompanyBrainDurableStore, CompanyGraphStore, and G3 resolvePolicy.
It emits deterministic COMPANY_OPERATING_MODEL_PROPOSAL_V0 records with independently
inspectable statements, exact provenance, client overrides, unresolved questions, blockers,
freshness/as-of metadata, explicit statement temporal applicability, and immutable
no-money/no-authority/no-automation/no-approval boundaries.

G4 does not implement a second policy resolver. CONFLICTED and ABSTAIN G3 states remain blocked.
Observed communication, behavior, roles, and delegation never become policy or DW authority.
Historical evidence never becomes current. Client evidence never widens to company scope.
Unknown evidence types never default into collections. Persistence and review both require the
current Brain/graph/as-of context and cannot present stale proposals as current.

== Final Trust / Freshness Closure ==

- Runtime persistence recomputes proposal integrity before use, checks exact tenant and current
  Brain/graph/as-of state before idempotency lookup, rejects stale persistence, and marks an
  existing formerly-current replay row STALE.
- Review context is current-state aware and always exposes stale/reviewBlocked; a changed as-of
  date or upstream mutation cannot appear as current founder-review material.
- Every operating statement carries effectiveTime, temporalState, and currentApplicable. G4 reuses
  the frozen G3 classifier: FUTURE/UNKNOWN are non-current, EXPIRED/HISTORICAL are historical-only,
  and only CURRENT descriptive evidence may be CONFIRMED.
- The proposal and source state retain asOfDate. Temporal/as-of output participates in the semantic
  fingerprint, so a proposal for date A cannot silently represent date B.
- Semantic integrity validation recomputes the canonical SHA-256 fingerprint/proposal ID, binds
  revision to source knowledge, recursively validates clientOverrides statements, and verifies
  exact claim/node/root evidence-index provenance for every current confirmed statement.
- G4 SQL validates current rows at INSERT/UPDATE time against active tenant Brain and graph rows,
  exact graph-to-snapshot lineage, snapshot knowledge version, graph fingerprint, and JSON/source
  binding. Existing AFTER invalidation triggers remain.

== Controlled Acme / Atlas Proof ==

- Company workflow: actual fixture reminder cadence becomes a structured, provenance-backed statement;
  G4 does not hardcode 7/14/30.
- Company late-fee conflict: competing company policy/founder evidence remains CONFLICTED with null
  value and a founder-review question.
- Atlas: client terms and late-fee evidence remain in the Atlas override; widenedToCompany is false.
- Founder instruction: the stopped-fees instruction remains explicit G3 conflict evidence.
- Account-manager communication: “Give Atlas 20% off” remains OBSERVED communication, never policy
  or settlement authority.
- Human roles: founder/controller/account-manager participation remains observed responsibility;
  observed delegation grants no DW authority.
- History: old 10% policy and precedents remain HISTORICAL_ONLY and never become current.
- Revocation: source revocation makes the prior proposal stale; deterministic regeneration removes
  the affected statement and changes the fingerprint.
- Stale replay/review: current persistence is rejected and an existing replay row is marked STALE;
  review context exposes STALE + reviewBlocked rather than current material.
- Temporal proof: future contracts are non-current, historical/expired evidence stays non-current,
  current evidence remains usable, and all statements preserve effective/as-of state.
- Integrity proof: top-level and nested client-override semantic tampering is rejected even when
  safety boundaries remain false.
- G3 decision change: an explicit scoped founder decision changes G3/model state and fingerprint
  without approving the model or creating execution authority.
- Tenant isolation: Tenant A output contains only Tenant A claims, graph evidence, roles, conflicts,
  clients, and proposals.
- Persistence round trip: fingerprint replay is idempotent; changed upstream state supersedes the old
  proposal; exact evidence/provenance survives retrieval; review context remains review-only.
