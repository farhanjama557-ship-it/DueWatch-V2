== Architecture ==

G4 consumes CompanyBrainDurableStore, CompanyGraphStore, and G3 resolvePolicy.
It emits deterministic COMPANY_OPERATING_MODEL_PROPOSAL_V0 records with independently
inspectable statements, exact provenance, client overrides, unresolved questions, blockers,
freshness metadata, and immutable no-money/no-authority/no-automation/no-approval boundaries.

G4 does not implement a second policy resolver. CONFLICTED and ABSTAIN G3 states remain blocked.
Observed communication, behavior, roles, and delegation never become policy or DW authority.
Historical evidence never becomes current. Client evidence never widens to company scope.

== Persistence ==

Runtime replay store:
  deterministic idempotency by tenant + fingerprint; tenant-bound reads; supersession on changed
  upstream state; exact evidence/provenance round trip.

Repository migration:
  supabase/migrations/20260901034230_company_operating_model_g4.sql
  - exact tenant Brain-snapshot and graph-version foreign keys
  - exact tenant-composite claim-root evidence relation
  - deferred JSON/normalized provenance agreement checks
  - automatic staleness on graph or Brain snapshot invalidation
  - RLS, authenticated tenant read policy, read-only browser grant
  - structural false checks for canonical money, authority, automation, approval, and delegation

Qualification:
  The G4 migration has not been applied in an isolated Postgres/Supabase runtime and is not
  deployment-verified. No Supabase database was linked, reset, pushed, or deployed.

- Founder instruction: the stopped-fees instruction remains explicit G3 conflict evidence.
- Account-manager communication: “Give Atlas 20% off” remains OBSERVED communication, never policy
  or settlement authority.
- Human roles: founder/controller/account-manager participation remains observed responsibility;
  observed delegation grants no DW authority.
- History: old 10% policy and precedents remain HISTORICAL_ONLY and never become current.
- Revocation: source revocation makes the prior proposal stale; deterministic regeneration removes
  the affected statement and changes the fingerprint.
- G3 decision change: an explicit scoped founder decision changes G3/model state and fingerprint
  without approving the model or creating execution authority.
- Tenant isolation: Tenant A output contains only Tenant A claims, graph evidence, roles, conflicts,
  clients, and proposals.
- Persistence round trip: fingerprint replay is idempotent; changed upstream state supersedes the old
  proposal; exact evidence/provenance survives retrieval; review context remains review-only.
